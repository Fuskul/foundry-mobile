Foundry Mobile

Мобильный спутник для ваших игр в Foundry: лист персонажа, настоящие броски системы и чат — с телефона. Состоит из модуля для Foundry и приложения. Интерфейс на русском и английском, WFRP4e сейчас, другие системы — через адаптеры. Проверено на Foundry 14.367 и WFRP4e 9.6.4.

Модуль-мост проверен на живой игре Лист и броски WFRP4e работают Приложение собрано, RU/EN APK — собирается на GitHub

Из чего это состоит

Две части, одна сборка интерфейса используется дважды.

Data/modules/fvtt-mobile-bridge

Модуль для Foundry

Готовит данные листа и кидает кубы настоящим движком WFRP4e. Установлен, включён и проверен прямо в вашем мире.

app/ → APK

Приложение

React + Capacitor, собирается в APK на GitHub. Открыть тот же интерфейс просто ссылкой из папки модуля нельзя: Foundry намеренно отдаёт любые .html из папки данных как текст, защищаясь от вредоносных страниц.

Почему без модуля не обойтись

Телефон умеет войти в Foundry и прочитать документы напрямую — но сырой документ это ещё не лист персонажа. Итог навыка, очки брони, максимум ран и вся механика проверки (УУ, криты, промахи, локация попадания, Преимущество, эффекты талантов) считаются кодом системы, который живёт только внутри клиента Foundry.

Поэтому приложение не переписывает правила заново. Оно просит модуль в браузере Мастера подготовить лист и бросить кубы — и в чат падает обычная карточка WFRP4e, неотличимая от броска с компьютера.

Отсюда главное ограничение: хотя бы один обычный клиент Foundry (обычно Мастер) должен быть в игре. Иначе приложение честно скажет «модуль-мост не найден» и лист не откроется.

Что делать дальше

Первые два шага уже пройдены.

  1. Модуль установлен и включён

    Foundry 14.367, мир test123, система WFRP4e 9.6.4. Модуль загрузился без ошибок.

  2. Лист и броски проверены

    Характеристики, навыки с итогами, таланты, черты, броня, состояния — читаются верно. Броски дают настоящие карточки WFRP4e.

  3. Выложить репозиторий

    GitHub Desktop: Commit to main → Publish repository. Сборка APK запустится сама.

  4. Скачать APK

    На GitHub вкладка Actions → зелёная галочка → раздел Artifacts → foundry-mobile-apk.

  5. Войти и прислать отчёт

    Адрес сервера, имя игрока, пароль. Если не пустит — «Ещё» → «Диагностика» → «Скопировать отчёт»: он покажет, на каком шаге цепочка рвётся.

Честно о рисках

  • Модуль проверен, приложение — ещё нет. Лист, броски, изменение ран и чат отработали на живом мире. Не проверена только та часть, что живёт в самом приложении: вход и соединение с игрой. Для этого в приложении есть пошаговая диагностика.
  • Через браузер открыть нельзя. Foundry отдаёт любые .html из папки данных как текст — защита от вредоносных страниц в модулях. Поэтому интерфейс живёт только в приложении.
  • Нужен онлайн-Мастер. Без браузерного клиента с модулем лист не соберётся. Со временем часть данных можно будет читать напрямую, но броски всегда останутся за модулем.
  • Доверие к отправителю. Foundry пересылает события модулей без подписи, поэтому мост верит полю «от кого». Права на персонажа проверяются, но для публичного релиза сюда нужно добавить подпись запроса.
  • Карты пока нет. Сцены, токены и перемещение — отдельная большая задача, в 0.1 её нет сознательно.

Как получится APK

Android Studio ставить не нужно. Проект собирается в облаке GitHub: вы создаёте репозиторий, я кладу туда код, и при каждом изменении GitHub сам собирает foundry-mobile-debug.apk — его останется скачать и поставить на телефон. Для публичного релиза тот же процесс выкладывает и приложение, и архив модуля.

Что уже отработало на вашем мире: лист «Вьюна» со всеми характеристиками и итогами навыков, проверка Оружия (цель 43, УУ −4, локация — голова), проверка Атлетики (цель 48, УУ +3), изменение ран с откатом, отправка /r 1d100 в чат и таблица сложностей от «Очень лёгкой (+60)» до «Невозможной (−50)».
